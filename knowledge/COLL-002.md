## 1. 为什么要比较 ArrayList 和 LinkedList

两者都实现了 List 接口，都可以保存有序、允许重复的元素，但底层数据结构完全不同：

- `ArrayList` 使用可动态扩容的数组保存元素。
- `LinkedList` 使用双向链表保存节点，每个节点关联前驱、后继和元素值。

这会影响随机访问、插入删除、遍历、内存占用和 CPU 缓存局部性。面试不能只回答“数组查询快、链表增删快”，必须说明操作发生的位置、是否已经定位到节点，以及移动元素或遍历定位的成本。

## 2. 学习目标

学完后应能够：
- 解释 ArrayList 的底层数组、容量、扩容和元素移动。
- 解释 LinkedList 的双向节点结构、首尾指针和索引定位。
- 区分时间复杂度、均摊复杂度与实际运行性能。
- 结合访问模式、数据规模和内存开销进行选型。

## 3. ArrayList 的底层机制

### 3.1 数据结构

ArrayList 内部使用数组保存元素引用。数组本身长度固定，但 ArrayList 会在容量不足时创建更大的数组，再把旧数组中的元素复制过去，从而对外提供动态增长的效果。

需要区分两个概念：

- **size：** 当前集合中实际元素的数量。
- **capacity：** 底层数组能够容纳的元素数量。

因此，size 不等于 capacity。删除元素通常会减少 size，并将对应位置之后的元素向前移动；底层数组容量通常不会因为每次删除就立即缩小。

### 3.2 添加元素的过程

以尾部追加为例：

1. 检查当前数组是否还有可用位置。
2. 如果容量足够，将元素引用写入数组末尾。
3. 更新元素数量。
4. 如果容量不足，先分配更大的数组，将旧元素复制过去，再写入新元素。

示意代码：

```java
List<String> names = new ArrayList<>();
names.add("张三");
names.add("李四");
names.add("王五");
```

### 3.3 扩容与均摊 O(1)

在常见 OpenJDK 实现中，ArrayList 容量不足时会按一定增长策略扩容。JDK 8/17/21 常见实现采用约 1.5 倍的增长策略，但不要把增长因子当成 List 接口规范；实现细节可能随版本变化。

单次扩容需要创建新数组并复制已有元素，成本为 O(n)。但扩容不会在每次追加时发生。把连续多次追加的总成本平均到每次操作上，尾部追加通常可视为**均摊 O(1)**。

均摊 O(1) 不表示每次追加都只执行常数次操作，而是表示一系列追加操作的平均成本为常数级。

### 3.4 插入与删除

在中间位置插入元素，需要将插入位置及其后的元素整体向后移动，为新元素腾出空间；删除中间元素则需要将后续元素向前移动以填补空位。

因此：
- 尾部追加：通常均摊 O(1)。
- 按索引读取：O(1)。
- 按值查找：O(n)。
- 中间插入或删除：移动元素，通常 O(n)。

如果业务频繁在头部插入或删除，ArrayList 需要移动大量元素，通常不是理想选择。

## 4. LinkedList 的底层机制

### 4.1 双向链表结构

LinkedList 的每个节点通常保存三个部分：

- 前驱节点引用。
- 当前元素值。
- 后继节点引用。

LinkedList 维护首节点和尾节点引用。通过首尾指针，可以在两端进行插入和删除，而不需要移动其他节点。

概念结构：

```text
null <- [前驱 | A | 后继] <-> [前驱 | B | 后继] <-> [前驱 | C | 后继] -> null
          first                                      last
```

实际实现中节点是内部对象，图中仅用于说明节点之间的连接关系。

### 4.2 按索引访问为什么是 O(n)

链表没有连续数组下标。要获取索引为 i 的元素，必须从靠近目标的一端开始，沿着前驱或后继引用逐个移动，直到定位目标节点。

常见实现会根据索引位置选择从头部或尾部开始查找，以减少平均遍历距离，但最坏情况下仍然需要遍历线性数量的节点，因此按索引访问是 O(n)。

### 4.3 插入和删除的复杂度边界

“链表插入删除是 O(1)”这句话缺少一个重要前提：**必须已经拿到目标位置对应的节点，或者能够以 O(1) 方式定位该位置。**

- 已经持有目标节点引用，在该节点附近插入或删除：修改有限个指针，通常 O(1)。
- 先通过索引寻找目标位置，再插入或删除：定位需要 O(n)，整体仍为 O(n)。
- 在头部或尾部插入、删除：LinkedList 维护首尾引用，通常 O(1)。

这也是面试中最容易被追问的边界。

## 5. 复杂度对比

| 操作 | ArrayList | LinkedList | 说明 |
|---|---:|---:|---|
| 按索引读取 | O(1) | O(n) | 链表需要遍历定位 |
| 按值查找 | O(n) | O(n) | 两者都可能逐个比较 |
| 尾部追加 | 均摊 O(1) | O(1) | ArrayList 偶尔扩容 |
| 头部插入 | O(n) | O(1) | 数组需移动元素 |
| 中间插入 | O(n) | O(n) | 链表定位成本不能忽略 |
| 头部删除 | O(n) | O(1) | 数组需移动后续元素 |
| 中间删除 | O(n) | O(n) | 链表查找位置通常是 O(n) |
| 顺序遍历 | O(n) | O(n) | 实际性能还受内存布局影响 |

复杂度表描述的是典型操作模型，不等于实际耗时排名。数据规模、元素访问模式、对象分配、CPU 缓存和垃圾回收都会影响真实表现。

## 6. 为什么 ArrayList 的遍历通常更快

ArrayList 的元素引用连续存放在底层数组中。顺序访问时，CPU 更容易利用缓存行和硬件预取机制。

LinkedList 的节点通常是分散分配的对象。遍历时需要不断读取当前节点中的 next 引用，再跳转到下一个节点，存在指针追踪和较差的缓存局部性；每个节点还额外保存前驱、后继引用，带来对象和内存开销。

因此，即使两者顺序遍历的时间复杂度都是 O(n)，ArrayList 在很多实际场景中仍然更快、内存效率更高。

## 7. 遍历方式与隐藏的性能陷阱

对于 ArrayList，按索引遍历通常是 O(n)：

```java
for (int i = 0; i < list.size(); i++) {
    String value = list.get(i);
    // 处理元素
}
```

对于 LinkedList，按索引逐个读取可能变成 O(n²)：每次 get(i) 都需要重新定位节点，累计遍历成本很高。

LinkedList 应优先使用迭代器或增强 for 循环顺序遍历：

```java
for (String value : linkedList) {
    // 处理元素
}
```

迭代器沿着节点链接向后移动，整体遍历为 O(n)。迭代器的工作机制和结构性修改检测将在 COLL-008 深入讲解。

## 8. 选型原则

| 需求 | 通常优先考虑 | 原因 |
|---|---|---|
| 按索引读取较多 | ArrayList | 随机访问 O(1) |
| 尾部追加、顺序遍历 | ArrayList | 连续存储、缓存局部性好 |
| 中间位置频繁插入删除，且已持有节点迭代器 | LinkedList 可能适合 | 定位后修改链接成本低 |
| 需要双端队列能力 | 优先评估 ArrayDeque | 通常比 LinkedList 更节省节点开销 |
| 普通业务列表 | 通常先选 ArrayList | 通用性和实际性能通常更好 |

不要为了“链表插入删除是 O(1)”就默认选择 LinkedList。业务代码通常先按索引、业务键或迭代器定位元素，定位成本必须计入总成本。

## 9. 代码示例：迭代器位置上的插入

LinkedList 的 ListIterator 可以在迭代器当前位置插入或修改元素。示例：

```java
import java.util.LinkedList;
import java.util.ListIterator;

public class LinkedListExample {
    public static void main(String[] args) {
        LinkedList<String> names = new LinkedList<>();
        names.add("张三");
        names.add("王五");

        ListIterator<String> iterator = names.listIterator();
        while (iterator.hasNext()) {
            String name = iterator.next();
            if ("张三".equals(name)) {
                // 在迭代器当前位置插入元素
                iterator.add("李四");
            }
        }

        System.out.println(names); // [张三, 李四, 王五]
    }
}
```

这里的重点不是证明 LinkedList 所有插入都是 O(1)，而是说明迭代器已经维护了当前位置，插入时可以直接修改相邻节点链接。迭代器本身如何移动以及修改规则，需要结合 ListIterator 契约理解。

## 10. 常见误区

1. **误区：LinkedList 插入删除永远是 O(1)。**  
   修正：只有定位完成后的节点链接修改通常是 O(1)；按索引定位本身通常是 O(n)。

2. **误区：ArrayList 每次 add 都要扩容。**  
   修正：只有容量不足时才扩容，尾部追加的均摊复杂度通常是 O(1)。

3. **误区：两者遍历都是 O(n)，性能就一样。**  
   修正：复杂度相同不代表常数成本相同；连续数组通常有更好的缓存局部性和内存效率。

4. **误区：LinkedList 适合所有频繁插入删除的场景。**  
   修正：如果每次都需要先查找位置，定位成本仍然存在；还要考虑节点对象分配和内存开销。

5. **误区：ArrayList 删除元素后一定立即缩容。**  
   修正：删除通常只调整元素和 size，不意味着底层数组立即缩小。

6. **误区：ArrayList 是线程安全的。**  
   修正：普通 ArrayList 不保证并发修改安全。并发场景需要明确线程封闭、外部同步或并发数据结构策略。

## 11. 工程场景：批量清算任务的内存队列

假设一个批处理服务从数据库读取一批待处理记录，在内存中按顺序校验并生成下游请求：

- 主要操作是顺序追加、遍历和按下标读取：通常优先考虑 ArrayList。
- 如果要从队列两端持续取放任务：应评估 Deque 或 BlockingQueue，而不是因为 LinkedList 支持双端操作就直接选它。
- 如果多线程消费者共同处理任务：普通 ArrayList/LinkedList 都不是合适的并发任务队列，应考虑 BlockingQueue 等并发容器。
- 如果数据量很大，还应评估分批读取、背压和内存上限，避免一次性加载造成堆压力。

集合选型必须服从业务访问模式和并发模型，而不是只看某个单独操作的理论复杂度。

## 12. 高频面试问题

### 问题 1：ArrayList 和 LinkedList 的底层结构有什么区别？

ArrayList 基于动态数组，LinkedList 基于双向链表。前者随机访问快、连续遍历通常更高效；后者两端操作方便，但按索引定位需要遍历，并且节点对象有额外内存成本。

### 问题 2：ArrayList 扩容为什么是均摊 O(1)？

单次扩容需要分配新数组并复制旧元素，成本为 O(n)。但扩容不是每次追加都发生，按一系列连续追加操作的总成本平均计算，尾部追加为均摊 O(1)。

### 问题 3：LinkedList 在什么情况下插入是 O(1)？

当已经持有目标节点或迭代器位置时，修改相邻节点的前驱、后继引用只需要常数次指针操作。若需要先按索引定位，则整体操作通常仍是 O(n)。

### 问题 4：为什么 LinkedList 不适合按索引遍历？

每次 get(index) 都需要从头部或尾部遍历定位。连续执行 n 次按索引读取，累计可能达到 O(n²)。应使用迭代器进行顺序遍历。

### 问题 5：为什么实际项目中 ArrayList 往往更常见？

大多数业务列表以顺序遍历、尾部追加和随机读取为主。ArrayList 的连续存储带来更好的缓存局部性，节点和指针开销更低，综合性能通常更好。

### 问题 6：如果需要频繁在两端插入和删除，应该选什么？

先明确是否需要线程安全。单线程普通双端队列通常优先评估 ArrayDeque；多线程生产消费通常评估 BlockingQueue。LinkedList 也实现 Deque，但不是默认最优选项。

## 13. 自测题

每题 2 分，共 10 分。建议先独立作答。

### 题 1：复杂度判断

ArrayList 在尾部追加元素的典型复杂度是什么？

A. 每次严格 O(n)  
B. 均摊 O(1)  
C. O(log n)  
D. O(n²)

**答案：B。** 容量足够时直接写入；容量不足时扩容复制，但从一系列操作的总成本看，尾部追加为均摊 O(1)。

### 题 2：链表插入

LinkedList 在什么条件下可以在 O(1) 时间完成中间插入？

A. 只要调用 add(index, value) 就一定 O(1)  
B. 已经定位到目标节点或迭代器位置  
C. 链表元素数量少于 1000  
D. 使用增强 for 循环

**答案：B。** 修改节点链接是 O(1)，但定位节点可能需要 O(n)。

### 题 3：遍历复杂度

对 LinkedList 执行以下操作，整体最可能是什么复杂度？

```java
for (int i = 0; i < list.size(); i++) {
    list.get(i);
}
```

A. O(n)  
B. O(log n)  
C. O(n²)  
D. O(1)

**答案：C。** 每次 get(i) 都可能遍历定位，累计成本为 O(n²)。

### 题 4：实际性能

ArrayList 和 LinkedList 顺序遍历都是 O(n)，为什么 ArrayList 通常仍更快？

A. ArrayList 的复杂度是 O(1)  
B. LinkedList 不支持遍历  
C. ArrayList 连续存储，通常具有更好的缓存局部性和更低的节点开销  
D. LinkedList 每次遍历都会排序

**答案：C。** 复杂度只描述增长趋势，不能体现缓存命中率、指针追踪和内存分配等常数成本。

### 题 5：双端队列选型

单线程场景下，需要高效地从头尾两端添加和删除元素，通常应优先评估哪种实现？

A. ArrayDeque  
B. TreeMap  
C. HashSet  
D. CopyOnWriteArrayList

**答案：A。** ArrayDeque 专门提供双端队列语义，通常比使用 LinkedList 承担同类任务更节省节点开销。
