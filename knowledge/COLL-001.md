## 1. 为什么需要学习集合框架

后端程序需要处理数量不固定、需要动态增删查改的数据。例如：批量支付指令、待处理消息、用户权限集合、按业务编号索引的记录等。

如果只使用数组，程序需要自行管理容量、移动元素、查找和去重。集合框架把这些常见数据结构和操作抽象成统一接口，并提供不同实现，让业务代码可以根据需求选择合适的数据结构。

学习集合框架，重点不是背诵类名，而是回答四个问题：

1. 数据是否允许重复？
2. 是否需要保持插入顺序或排序？
3. 主要操作是按索引访问、按键查找，还是队列式处理？
4. 是否存在多个线程并发读写？

## 2. 学习目标

## 3. 集合框架的整体结构

Java 集合框架主要由两条核心接口体系构成：以 `Collection` 为根的元素集合体系，以及以 `Map` 为核心的键值映射体系。

```text
Iterable<E>
  └── Collection<E>
       ├── List<E>       有序、允许重复
       ├── Set<E>        不允许重复
       └── Queue<E>      面向排队处理
            └── Deque<E> 双端队列

Map<K, V>                键值映射，不属于 Collection
  ├── SortedMap<K, V>
  │    └── NavigableMap<K, V>
  └── 常见实现：HashMap、LinkedHashMap、TreeMap、
               Hashtable、ConcurrentHashMap
```

上图表达的是主要接口关系和常见实现，不是完整的类继承图。比如 `ArrayList`、`LinkedList`、`HashSet` 等是具体实现类；`List`、`Set`、`Queue` 则是接口。

### 3.1 Iterable 与 Collection

`Iterable<E>` 表示对象可以提供迭代器，因此可以用于增强 for 循环。它定义了 `iterator()` 等迭代相关能力。

`Collection<E>` 在可迭代能力之上，进一步定义集合常见操作，例如：

- `add(E)`、`remove(Object)`：添加和删除元素。
- `contains(Object)`：判断是否包含元素。
- `size()`、`isEmpty()`：查看元素数量和是否为空。
- `clear()`：清空集合。
- `iterator()`：获取迭代器。

注意：`Collection` 是接口，不负责规定所有实现必须使用哪一种底层数据结构，也不承诺所有操作具有相同的时间复杂度。

### 3.2 为什么 Map 不属于 Collection

`Collection` 面向的是一组独立元素；`Map` 面向的是键到值的映射关系。

二者的核心操作模型不同：

- Collection：添加元素、删除元素、遍历元素。
- Map：根据键设置值、根据键读取值、删除键值映射、遍历键或键值对。

Map 的键具有唯一性：同一个键再次放入新值，会替换该键原来的值，而不是在 Map 中形成第二个相同键。

Map 提供 `keySet()`、`values()` 和 `entrySet()` 等视图，供调用者以集合方式遍历键、值或键值对。这不意味着 Map 本身继承了 Collection。

## 4. 三类核心 Collection 接口

### 4.1 List：有序且允许重复

List 是有序序列，通常保留元素的位置关系，并允许重复元素。它提供按索引访问和修改元素的能力，例如 `get(index)`、`set(index, value)`。

常见实现：

- `ArrayList`：基于动态数组，适合按索引访问和尾部追加。
- `LinkedList`：基于双向链表，同时实现 List 和 Deque；按索引访问通常需要遍历。

“有序”在 List 的语境中主要指元素具有位置次序，不等于自动按大小排序。向 List 依次添加 A、B、C，通常遍历顺序就是 A、B、C。

### 4.2 Set：不允许重复元素

Set 表示不包含重复元素的集合。判断重复通常依赖元素的相等性定义，具体实现还可能依赖哈希值或比较器。

常见实现：

- `HashSet`：基于哈希结构，不承诺迭代顺序。
- `LinkedHashSet`：在哈希结构基础上维护可预测的迭代顺序，通常为插入顺序。
- `TreeSet`：基于排序结构，按照自然顺序或指定比较器排序。

特别注意：如果对象作为 HashSet 元素，必须正确实现 `equals()` 与 `hashCode()` 契约。若对象在放入集合后，参与哈希计算的字段发生变化，可能导致后续查找和删除行为异常。

### 4.3 Queue 与 Deque：面向排队和两端操作

Queue 面向排队处理，通常体现先进先出（FIFO）语义，但具体队列实现也可能具有优先级等不同规则。

Queue 中有两组语义相近但失败处理不同的方法：

| 操作 | 失败时抛出异常 | 失败时返回特殊值 |
|---|---|---|
| 插入 | `add(e)` | `offer(e)` |
| 移除队首 | `remove()` | `poll()` |
| 查看队首 | `element()` | `peek()` |

例如，容量受限的队列已满时，`add` 可能抛出异常，而 `offer` 返回 false。队列为空时，`remove` 抛出异常，而 `poll` 返回 null。

Deque 是双端队列，允许从头部和尾部插入、移除和查看元素。它既可以作为队列，也可以作为栈使用。通常推荐使用 `ArrayDeque` 实现普通的栈或双端队列需求，而不是优先使用较早设计的 `Stack` 类。

## 5. Map 体系与常见实现

Map 的选择要同时考虑查找效率、顺序要求、排序要求和并发访问。

| 实现 | 主要特点 | 典型使用场景 | 关键注意点 |
|---|---|---|---|
| `HashMap` | 哈希表；不保证遍历顺序 | 按键快速查找 | 非线程安全；允许一个 null 键和多个 null 值 |
| `LinkedHashMap` | 维护可预测的迭代顺序 | 需要稳定遍历顺序、简单缓存策略 | 额外维护链表关系 |
| `TreeMap` | 按键排序 | 范围查询、按键有序遍历 | 操作通常为 O(log n) |
| `Hashtable` | 较早的同步 Map 实现 | 维护旧系统时可能遇到 | 设计较旧，不允许 null 键和值 |
| `ConcurrentHashMap` | 面向并发访问的 Map | 多线程共享键值数据 | 不允许 null 键和值；复合业务操作仍需考虑原子性 |

这里的时间复杂度是典型实现下的常见结论，不是接口层面对所有实现的保证。哈希表的查找通常具有良好的平均性能，但会受到哈希冲突、扩容、哈希分布和实现细节影响。

### 5.1 Map 的三个集合视图

- `keySet()`：返回键的 Set 视图。
- `values()`：返回值的 Collection 视图。
- `entrySet()`：返回键值对 Entry 的 Set 视图。

这些视图通常与原 Map 关联，并非简单复制一份独立数据。通过视图删除元素可能影响原 Map；对视图的修改能力取决于具体 Map 实现及该视图支持的操作。

如果需要同时读取键和值，通常优先遍历 `entrySet()`，避免对每个键再执行一次 `get(key)`。

## 6. 接口与实现：为什么要面向接口编程

业务代码应尽量依赖表达需求的接口，而不是过早绑定具体实现。

```java
// 业务只需要保存有序、允许重复的元素
List<String> paymentIds = new ArrayList<>();

// 业务只需要键值映射，不依赖具体哈希实现
Map<String, Integer> retryCounts = new HashMap<>();
```

变量类型使用接口，可以减少调用方对具体实现的依赖。但这并不意味着所有场景都应该把左侧类型写成接口：如果业务明确依赖某个实现独有的能力，或者需要表达更具体的约束，具体类型也可能合理。

设计时应先描述需求，再选择实现：

1. 需要按索引访问吗？考虑 List，重点比较 ArrayList 与 LinkedList。
2. 需要去重吗？考虑 Set，并确定是否需要顺序或排序。
3. 需要按键查值吗？考虑 Map，并确定是否需要排序或并发能力。
4. 需要先进先出或两端操作吗？考虑 Queue 或 Deque。
5. 多线程会共享并修改集合吗？选择并发集合，或设计外部同步和不可变数据策略。

## 7. 泛型与集合类型安全

集合接口普遍使用泛型表达元素类型或键值类型。

```java
List<String> names = new ArrayList<>();
names.add("Alice");
// names.add(100); // 编译错误：元素类型不匹配

String first = names.get(0);
```

泛型让编译器在编译阶段检查类型约束，减少取出元素时的强制类型转换。它并不意味着运行时所有泛型实参都完整保留；Java 泛型主要通过类型擦除实现，详细机制见 JAVA-004。

原始类型（例如直接使用 `List`）会绕过部分泛型检查，可能引入未经检查的警告和运行时类型转换异常。新代码应优先使用参数化类型。

## 8. 集合选择中的复杂度与工程权衡

复杂度不能脱离操作和实现讨论。以下为常见实现的典型情况：

| 结构 | 按索引读取 | 按值查找 | 尾部追加/插入 | 主要代价 |
|---|---:|---:|---:|---|
| ArrayList | O(1) | O(n) | 均摊 O(1) | 中间插入或删除需要移动元素 |
| LinkedList | O(n) | O(n) | 已定位节点后 O(1) | 节点对象和指针带来额外内存开销 |
| HashMap | 不适用 | 平均 O(1) 查找键 | 平均 O(1) 放入 | 哈希冲突、扩容、内存开销 |
| TreeMap | 不适用 | O(log n) 查找键 | O(log n) | 维护排序结构 |
| HashSet | 不适用 | 平均 O(1) 判断元素 | 平均 O(1) 添加 | 依赖哈希分布和正确的相等性契约 |

说明：

- O(1) 不代表耗时绝对固定，也不代表没有常数开销。
- ArrayList 的尾部追加是均摊 O(1)，扩容那一次可能需要复制数组。
- LinkedList 在已持有目标节点引用时，局部插入或删除可以是 O(1)；但从头或尾定位到任意索引通常需要 O(n)。
- HashMap 的平均复杂度依赖哈希分布和负载情况，不能将其说成任何情况下都严格 O(1)。
- 实际工程还要考虑内存占用、缓存局部性、数据规模、并发竞争和可维护性。

## 9. 并发安全边界

`ArrayList`、`HashMap`、`HashSet` 等常见基础集合实现不是为多个线程并发修改而设计的。并发读写时，不能仅凭“没有报错”判断结果正确。

常见策略包括：

1. **线程封闭：** 集合只由一个线程访问，不共享可变状态。
2. **外部同步：** 使用同一把锁保护所有相关读写操作。
3. **并发集合：** 例如 `ConcurrentHashMap`、`BlockingQueue`，根据并发访问模式选择。
4. **不可变或只读共享：** 构建完成后不再修改，减少共享可变状态。

注意：线程安全集合不等于业务流程天然原子。例如先 `get` 判断不存在，再 `put` 写入，若两个操作不是一个原子操作，仍可能发生竞态。应根据业务选择 `putIfAbsent`、`compute` 等原子方法，或用外部事务/锁维护更大范围的不变量。

## 10. 高频面试问题与回答要点

### 问题 1：Java 集合框架的整体结构是什么？

回答要点：

- 主要分为 Collection 和 Map 两条体系。
- Collection 下常见 List、Set、Queue。
- Map 表达键值映射，不继承 Collection。
- 接口定义操作契约，具体实现决定数据结构和性能特征。

### 问题 2：List、Set、Map 的核心区别是什么？

回答要点：

- List 是有位置次序、允许重复的元素序列。
- Set 用于表达不重复元素集合。
- Map 保存键值映射，键唯一，值可以重复。
- 选择时继续考虑排序、遍历顺序和并发要求。

### 问题 3：HashMap 和 TreeMap 怎么选？

回答要点：

- 只需要按键查找，且不要求排序时，通常考虑 HashMap。
- 需要按键排序、范围查询或有序遍历时，考虑 TreeMap。
- HashMap 常见操作平均 O(1)，TreeMap 常见操作 O(log n)。
- 还要考虑键的相等性/比较规则、数据规模和并发要求。

### 问题 4：为什么推荐面向接口编程？

回答要点：

- 将业务所需能力与底层实现解耦。
- 便于替换实现和测试。
- 但不能为了形式而忽略实现特有的能力和约束。

### 问题 5：HashMap 是线程安全的吗？

回答要点：

- HashMap 不保证并发修改安全。
- 多线程共享修改应考虑 ConcurrentHashMap、外部同步或线程封闭。
- 即使使用 ConcurrentHashMap，也要识别多个方法调用组合成的业务操作是否原子。

### 问题 6：Map 为什么不继承 Collection？

回答要点：

- Collection 的核心抽象是一组元素。
- Map 的核心抽象是键到值的映射。
- Map 的遍历视图可以转化为 Set 或 Collection，但这不改变其本身的抽象模型。

## 11. 工程场景：批量处理支付指令

假设服务接收一批支付指令，需要按业务编号去重、保留原始接收顺序，并统计每个编号的处理次数。

可以拆成不同的数据需求：

- 原始接收顺序：使用 List 保存接收记录。
- 编号去重并保留首次插入顺序：可考虑 LinkedHashSet。
- 按编号统计次数：可考虑 Map<String, Integer>。
- 多线程消费者之间传递任务：根据生产消费模型考虑 BlockingQueue，而不是直接共享一个普通 ArrayList。

示意代码：

```java
List<String> receivedIds = new ArrayList<>();
Set<String> uniqueIds = new LinkedHashSet<>();
Map<String, Integer> retryCounts = new HashMap<>();

for (String paymentId : incomingIds) {
    receivedIds.add(paymentId);
    uniqueIds.add(paymentId);
    retryCounts.merge(paymentId, 1, Integer::sum);
}
```

这段代码用于说明不同集合承担不同职责，不代表完整的生产级支付处理方案。实际系统还需要考虑持久化、幂等键约束、事务边界、并发更新、失败恢复和数据规模。

## 12. 自测题

建议先独立作答，再查看答案。每题 2 分，共 10 分。

### 题 1：接口关系

以下说法哪项正确？

A. Map 继承 Collection  
B. List 继承 Map  
C. Set 是 Collection 的子接口  
D. ArrayList 是 Collection 的接口

**答案：C。**

**解析：** Set 是 Collection 的子接口；Map 是独立的键值映射体系；ArrayList 是 List 的具体实现类。

### 题 2：需求选型

需要保存元素、允许重复、按插入位置访问，优先选择哪一类接口？

A. Set  
B. List  
C. Map  
D. SortedMap

**答案：B。**

**解析：** List 表达有位置次序、允许重复的元素序列。

### 题 3：顺序与去重

需要去重，同时希望迭代顺序与首次插入顺序一致，优先考虑哪种实现？

A. HashSet  
B. TreeSet  
C. LinkedHashSet  
D. PriorityQueue

**答案：C。**

**解析：** LinkedHashSet 维护可预测的迭代顺序，通常为插入顺序；HashSet 不承诺顺序，TreeSet 按比较规则排序。

### 题 4：复杂度判断

关于 ArrayList 和 LinkedList，哪项正确？

A. LinkedList 按索引读取通常是 O(1)  
B. ArrayList 中间插入通常不需要移动元素  
C. ArrayList 尾部追加通常为均摊 O(1)  
D. LinkedList 任意位置插入都严格为 O(1)

**答案：C。**

**解析：** ArrayList 尾部追加通常为均摊 O(1)；中间插入需要移动元素。LinkedList 按索引定位通常为 O(n)，只有已获得目标节点后局部插入才可为 O(1)。

### 题 5：并发边界

使用 ConcurrentHashMap 后，以下哪种说法正确？

A. 所有由多个方法组成的业务流程自动具备原子性  
B. 不需要再考虑并发竞态  
C. 单次原子方法可以提供相应的并发语义，但跨多个独立调用的复合操作仍需单独设计  
D. ConcurrentHashMap 允许 null 键

**答案：C。**

**解析：** 并发集合提供特定操作的并发安全保证，不会自动把任意多步业务逻辑合并为一个原子事务；ConcurrentHashMap 不允许 null 键和值。
